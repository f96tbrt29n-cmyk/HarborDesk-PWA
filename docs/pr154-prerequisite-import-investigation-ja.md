## 対象限定の追加計測

`tests/strategy-import-diagnostics.cjs` は当該テストでだけインストールする。イベントのtarget/currentTarget/ヒット要素/座標/状態、ボタンのWeakMap識別子・接続・位置・disabled・pointer-events、取込/保存/描画の入口と出口、戦略リストの保存値、スクロール呼出元、ヘッダー遷移を記録する。

記録はexposeBindingでテストrunnerへ送る。ページ再読込や終了でも消さず、testId/project/worker/retryで分けたJSONを退避する。初回失敗と再試行を同じファイルに上書きしない。診断の保存と製品の保存を区別し、製品の6保存キーは削除・初期化しない。

CIは対象の診断JSONと対象テストの画像/動画/traceだけを、ジョブが再試行で成功してもアップロードする。通常の失敗診断も維持。既存trace設定は変更しないため、初回失敗にtraceがなくても、その初回の実イベントJSONと画像/動画を保持する。診断回帰では人工的な覆い・ノード交換・ページ終了を使うが、製品側の再現とは扱わない。

計測はスタイル/位置の読取やrunnerへの通信を追加するため、タイミングを変える可能性がある。計測追加後の成功だけで元不具合の解消とは判断しない。取込関数・描画関数の挙動は同じ引数/this/戻り値/例外で委譲する。ユーザー操作を再実行する、待ちを挿入する、イベントを無効化する等の補正は加えない。

## 原因候補と不足する証拠

1. 宛先違い/重なり/取消：実イベントとヒット要素の失敗時記録が必要。
2. 入力中のノード差し替え：押下時のノードと描画前後の接続を比較する必要。
3. スクロール/ヘッダー/初期復元の競合：失敗時の位置変化と呼出スタックが必要。
4. 取込処理/保存/UI反映：取込関数が呼ばれたか、保存前後の戦略リストと返却値が必要。

いずれも未確定。今回の段階では根拠なく製品を変更しない。診断追加と製品修正は区別してコミットする。
