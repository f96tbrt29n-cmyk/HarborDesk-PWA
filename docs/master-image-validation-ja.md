# main578 の画像検証失敗と修正

2026-10-15。作業基準は main `8177700a120fac51e7f0773971a2fedece73ad3c`。PR151/152とは独立した `codex/master-image-validation`。製品・マスター・保存形式・版/build/cacheは変更しない。

## 原因と根拠

[公開run38619850193](https://github.com/f96tbrt29n-cmyk/HarborDesk-PWA/actions/runs/38619850193)は画像ソース検証の `866 !== 865` で停止。ブラウザーとDeploy Pagesは未実行。

自動同期8177700で、865形態から866形態になった。追加は「狭霧改二」ID902、削除なし。[固定上流マスター](https://github.com/Tibowl/api_start2/blob/23637be57ac23a7b4281f193b836fa568ead8ee4/start2.json)のID902・艦名・艦種・3装備枠と一致。狭霧改391の改造先902・必要Lv84とも一致。全プレイヤー形態のID集合も照合。ローカル自動生成データを手修正・削除する理由はない。

一方、[固定画像コミット](https://github.com/Nishisonic/gkcoi/tree/c6265b152e17a8ad6529fd1215f84ccd0304fce5/static/ship/card)には865画像があり、既存865形態のファイルが全て存在する。902.pngは一覧に存在せず、固定URLもHTTP404。新しい画像が追加されたわけではない。全マスターに固定画像があるという旧テストの仮定も成立しなくなったため、固定件数を866にするだけでは次のURL検査も失敗する。

[照合記録](master-image-validation-evidence.json)には上流コミット・取得JSONのSHA-256・追加/削除・画像コミットを記録した。全画像の表示内容を目視確認したという意味ではない。新しい画像URL・性能を推測で登録しない。

## 修正

`tests/ship-image-source.test.cjs` のみ機能的に修正。

- 件数固定を、画像対象ID集合と現行マスターID集合の完全一致・重複なしへ変更。マスターが画像側で欠落すると失敗する。
- 固定画像に存在しないマスターIDを `[902]` と明示。未確認の欠損を自動で許容しない。将来ほかの未収録艦や画像ソースの変更があれば再び検査が失敗し、出典・未登録表示の再確認を要求する。
- 既存全865形態について、固定画像URLとの一致を継続検査。902はURLなし・未検証状態・正しい個体ID/艦名・「画像未登録」/画像登録導線を検査する。
- カスタムURL、画像自動参照の無効化、従来設定の互換性を維持する。

未収録形態を別艦画像で埋めたり、マスターから除外したりしない。既存の画像フォールバックが正しく動作しており、製品コード変更は不要だった。画像未登録は当該艦の装備性能や攻略条件が全て検証済みという意味でもない。
