## 範囲とレビュー

- キーは各 `steps.next()` 用の一時Map。終了・yield・例外・取消後は既存finallyで元scopeへ復帰し、次stepへ表を持ち越さない。入れ子も別キー。
- snapshot／equipment参照差替えでは再構築。equipmentのin-place変更は次stepまたはscope外の次呼出しで反映する。型表factoryの差替え時は再利用しない。
- 公開 `hdShipDbMasterTypeMap` は変更せず毎回freshな可変Map。艦ごとのprofile／判定はキャッシュせず、配列の新規生成・既存の参照共有を維持。
- scopeを作る製品呼出し元はowned searchの同期／非同期 `steps.next()` の2箇所。現行の到達経路に装備マスターの書換えはなく、UI／同期通知は同期stepへ割り込まない。通常UIなどscope外の呼出しは従来どおり。
- 同じread-only step内でequipment自体をin-place編集する用途は対象外。将来その経路を追加するならopt-inの再検討が必要。恒久不変のマスターや永続cacheを仮定しない。

待機25ms/0ms、探索上限・beam・比較／取消処理、45秒試験／12秒expect、攻略判定・保存形式・版・SWは変更しない。
