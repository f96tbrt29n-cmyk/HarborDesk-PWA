# PR152: 診断画面の艦ID/公式名修復と読取り不能

基準7c32eba706eab5ed26d2561fc6e4efc88ee40fe8。対象は診断画面の「艦ID/公式名を修復」だけ。
フォーム・同期merge・undo・ローダーの完了済み限定対照は再実行しない。

## 仕様と経路

`[data-dx-ship-identity]` → `hdDXRepairShipIdentity()` → 確認 → 台帳R/保存編成Fを読取 →
`hdShipIdentityStatus` とマスターに基づきMASTER ID・公式名を修正 → R/Fを書込 →
台帳等を再描画・`hd:ship-identity-changed` → 診断画面再採取。
Lv・個体情報・装備/手動メモ・タグ・他行・保存編成metadataは保持、変更した台帳行のupdatedAtは更新する既存仕様。
存在しないID・ID未設定でもマスターで解決できるデータは従来どおり修復する。
健康診断で問題がなければ修復ボタン自体を提示しない。

旧コードはgetItemの実null・読取り例外・JSON構文エラーを[]/{}と見なし、両キーへ無条件書戻し。
修復は構造の読めるデータ中のID/名前を扱う機能であり、構文不正JSONや空文字から内容を推測復元する仕様はない。

## 修正前の独立した欠陥

新しい隔離context、元R文字列とown-propertyを維持し、実ボタンのcapture時にRのgetterだけnull化。
Chromium1回、retries0、45秒、同じ最終fixture/安全停止assertで修正前失敗を確認。
R/F書込2、完了イベント1、両キー元文字列不一致、警告なし。旧処理はRを[]へ上書きした。
初回trace・動画・画像・JSON・配信ソースを証拠rootのbeforeへ保持する。
これは制御した読取り異常後の上書き欠陥。旧自然保存実nullの発生原因再現ではない。

## 最小保護

修復入口で両キーの読取りを完了してから判断・書込みへ進む。
実null+現在のown-propertyあり、読取り例外、JSON構文エラー、空文字は警告してfalseで中止。
警告は再描画に消されない位置のrole=alertと既存toastで通知。完了イベント・成功再描画へ進めない。
読取り回復後に同じボタンから通常修復でき、警告を消す。
正常未保存（実null+ownなし）の[]/{}、構文の有効なデータの従来fallback/修復規則は維持する。
保存形式・永続マーカー・自動復元・SW・登録方式・期限は変更しない。

getItem→own→書込みは非原子的。キー存在も見えない異常は正常未保存と区別できない。
構文として有効だが不正schemaの値一般、別realm/同時更新、一般の書込み失敗/途中適用まで安全とはしない。
